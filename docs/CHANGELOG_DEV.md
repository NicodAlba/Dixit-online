## 2026-10-22 — DEV-002 — Finalización con cuentas registradas

- **Problema y evidencia:** reproducción HTTP en instancia aislada `127.0.0.1:18080`, H2 en memoria independiente. Registrar tres cuentas PLAYER mediante `POST /api/v1/auth/signup`, iniciar sesión, crear una partida, unir a los otros dos e iniciarla. Jugar seis turnos con carta del narrador, pista, cartas de los otros participantes y dos votos válidos por turno. El último voto del sexto turno devolvía HTTP 500: `Cannot invoke "Game.getTurns()" because "g" is null`. Un GET posterior mostraba `endDate=null`, cero ganadores, sexto turno en `SHOWING_CARDS` y solo un voto: rollback de la última transacción. La nueva prueba de integración también reprodujo la misma excepción antes del arreglo.
- **Comportamiento esperado:** una participación sin partida creada al registrar una cuenta no debe impedir calcular logros ni completar la última votación; deben persistir puntos, ganadores y finalización.
- **Solución:** filtrar partidas nulas exclusivamente en `checkTrickAchievements`, igual que ya hace `checkWinAchievements`. No se elimina el Player creado por registro ni se modifica el historial.
- **Archivos modificados:** `src/main/java/es/us/dp1/lx_xy_24_25/dixit/achievement/AchievementService.java`, `src/test/java/es/us/dp1/lx_xy_24_25/dixit/game/TurnServiceIntegrationTest.java` y este registro.
- **Justificación:** corrección de una línea en la causa reproducida, conservando servicios, transacciones y modelo. Referencias: D1 US23/US24 y R5/R6/R8/R9, D2 arquitectura por capas, D3 pruebas de logros y puntuación. No se reescriben los entregables.
- **Impacto:** permite completar partidas con usuarios registrados. No cambia puntuación, rotación, reglas de empate, permisos, API ni WebSockets.
- **Verificación y resultados:** compilación backend Java 21 correcta. `mvn -o -Dtest=TurnServiceIntegrationTest,AchievementServiceTest -Dspring.jpa.show-sql=false -Dspring.jpa.properties.hibernate.format_sql=false test`: 17 pruebas, cero fallos y cero errores. La regresión usa el servicio real de registro, recarga las asociaciones JPA, juega seis turnos, comprueba que no acaba antes del último voto y vuelve a cargar el estado tras flush/clear: finalización, votos, puntos, tres ganadores empatados y `Card.user` conservado con `Card.owner=null`. Repetición HTTP completa con otras tres cuentas nuevas: seis turnos completados, dos votos finales persistidos, ganador correcto y puntos 22/14/6, sin perder autoría de las cartas. Todas las acciones HTTP se hicieron contra una base efímera, sin tocar datos de otra instancia.

La primera ejecución de tests dentro del sandbox no pudo inicializar el agente de Mockito; fuera de esa restricción se reprodujo el error y se ejecutaron las 17 pruebas correctamente, sin modificar herramientas.
